# רשת המקוואות — מערכת ניהול (גרסה עצמאית)

פרויקט React מלא שממיר את הדוגמה מהצ'אט לאתר אמיתי, עם בסיס נתונים אמיתי
ב-Firebase (Firestore). המדריך הזה מסביר איך לפרוס את זה **בלי טרמינל בכלל** —
הכל דרך הדפדפן, באמצעות GitHub.

---

## כבר יש לך אתר חי מגרסה קודמת? זה מה שהשתנה ומה לעדכן

הגרסה הזו הוסיפה: כניסת Google למנהלים ולבלניות מהטלפון האישי, תמיכה בכמה
מקוואות, וקובץ חדש (`src/auth.js`). כדי לעדכן אתר קיים:

1. בתוך ה-repository שלך ב-GitHub → **Add file → Upload files**
2. לגרור שוב את **כל** תוכן התיקייה שהורדת (כולל התיקייה הנסתרת `.github`) —
   GitHub ידרוס קבצים קיימים עם אותו שם, ויוסיף את `src/auth.js` החדש
3. **Commit changes** — זה יפעיל בנייה ופריסה אוטומטית, בדיוק כמו קודם
4. **חובה גם:** לבצע את שני השלבים החדשים למטה ("הפעלת התחברות" ו-עדכון
   כללי ה-Firestore) — בלעדיהם הכניסה למנהל/בלנית לא תעבוד

אם זו הפעם הראשונה שלך, אפשר לדלג לישר להמשך המדריך.

## המסלול: GitHub בלבד (בלי טרמינל)

### שלב 1 — יצירת Repository ב-GitHub

1. כניסה ל-**github.com**, התחברות (או יצירת חשבון חינמי)
2. **"New repository"** (כפתור ירוק) → שם, למשל `mikveh-management` →
   לוודא שהוא **Public** או **Private** לפי מה שנוח לך → **Create repository**
3. חשוב: ה-branch הראשי חייב להיקרא **`main`** (זו ברירת המחדל היום ב-GitHub,
   כך שבדרך כלל אין צורך לשנות כלום)

### שלב 2 — העלאת כל קבצי הפרויקט

1. בעמוד ה-repo החדש (הריק), ללחוץ על הקישור **"uploading an existing file"**
2. לחלץ את ה-zip שקיבלת ממני, ו**לגרור את כל התוכן** מתוך התיקייה (כולל
   התיקייה הנסתרת `.github`, `src`, `index.html`, `package.json` וכל השאר)
   לתוך אזור ההעלאה בדפדפן
   - ⚠️ תיקיות נסתרות (ששמן מתחיל בנקודה, כמו `.github` ו-`.gitignore`)
     לפעמים לא נגררות אוטומטית מהגרירה הראשונה של כל התיקייה — אם בסיום
     ההעלאה את לא רואה תיקיית `.github/workflows` ב-GitHub, תצטרכי לגרור
     אותה בנפרד. זו התיקייה **הכי חשובה** — בלעדיה הפריסה האוטומטית לא תפעל.
3. למטה, **"Commit changes"**

### שלב 3 — הפעלת GitHub Pages

1. בתוך ה-repo, לשונית **"Settings"** (למעלה)
2. בתפריט הצד → **"Pages"**
3. תחת **"Build and deployment" → "Source"**, לבחור **"GitHub Actions"**
   (לא "Deploy from a branch")
4. זהו — אין צורך ללחוץ שום דבר נוסף כאן

### שלב 4 — מעקב אחרי הבנייה האוטומטית

1. לשונית **"Actions"** בתוך ה-repo
2. אמור להופיע ריצה בשם "Deploy to GitHub Pages" עם עיגול צהוב מסתובב
   (כ-1-2 דקות) ואז ✅ ירוק
3. כשהיא מסתיימת בהצלחה, לחזור ל-**Settings → Pages** — תופיע שם הכתובת
   החיה של האתר (בפורמט `https://<username>.github.io/mikveh-management/`)

מעכשיו, **כל פעם שתעלי/תעדכני קובץ ב-GitHub** (שוב, בגרירה בדפדפן, בלי
טרמינל), הפריסה תרוץ מחדש אוטומטית ותעדכן את האתר החי תוך דקה-שתיים.

## שלב חובה נוסף (חד-פעמי): פתיחת הרשאות הכתיבה ב-Firestore

כשיצרת את מסד הנתונים ב-Firebase בחרת **Production mode** — המצב הזה חוסם
**את כל** הקריאה/כתיבה כברירת מחדל, מטעמי אבטחה. כדי שהאתר יוכל בכלל לשמור
נתונים, צריך להדביק את כללי ההרשאה **פעם אחת**, ישירות בממשק הדפדפן של
Firebase (גם זה בלי טרמינל):

1. כניסה ל-https://console.firebase.google.com → הפרויקט שלך (`mikveh-bl`)
2. **Databases & Storage → Firestore → לשונית "Rules"**
3. למחוק את מה שכתוב שם, ולהדביק את התוכן המלא של הקובץ `firestore.rules`
   שנמצא בפרויקט שהורדת ממני
4. **"Publish"**

📌 **כבר הדבקת כללים בעבר?** קובץ ה-`firestore.rules` התעדכן בגרסה הזו
(עכשיו דורש התחברות, ולא פתוח לגמרי) — כדאי לחזור על השלבים למעלה ולהדביק
את הגרסה המעודכנת.

⚠️ הכללים האלה דורשים "מישהו מחובר" (כולל התחברות אנונימית) אבל לא בודקים
*מי* — האכיפה של מי מנהל ומי בלנית מאושרת קורית בתוך האפליקציה עצמה (מסך
"הרשאות"), לא ברמת Firestore. יש הערה מפורטת על כך בתוך הקובץ עצמו.

## שלב חובה נוסף (חד-פעמי): הפעלת התחברות (Google + אנונימי)

הגרסה הזו הוסיפה כניסה עם חשבון Google (למנהלים ולבלניות שנכנסות מהטלפון
האישי), ולכן צריך להפעיל את זה **פעם אחת** בממשק של Firebase:

1. כניסה ל-https://console.firebase.google.com → הפרויקט שלך
2. **Build → Authentication** (או "Databases & Storage" בממשק החדש — Authentication
   נמצא כפריט נפרד תחת "Security" בתפריט הצד)
3. **Get started** (אם זו הפעם הראשונה)
4. בלשונית **Sign-in method**, להפעיל שתי שיטות התחברות:
   - **Google** — ללחוץ, להפעיל את המתג, לבחור אימייל תמיכה, **Save**
   - **Anonymous** — ללחוץ, להפעיל את המתג, **Save**
     (זה מה שמאפשר לתושבות ולטאבלט המותקן לשמור נתונים בלי חשבון Google בכלל —
     רק מנהלים ובלניות שנכנסות מהטלפון האישי שלהן צריכות בפועל להתחבר עם Google)
5. עדיין בתוך Authentication → לשונית **Settings → Authorized domains** →
   **Add domain** → להוסיף את הדומיין של האתר החי שלך (למשל
   `aryeminkov-maker.github.io` — **בלי** `https://` ובלי הנתיב שאחריו)
   - ⚠️ בלי הצעד הזה, כפתור "התחברות עם Google" ייכשל עם שגיאת
     `auth/unauthorized-domain`.

## בדיקה שהכל עובד

1. לפתוח את הכתובת החיה מ-GitHub Pages — היא אמורה לפתוח ישירות בממשק
   הציבורי (דף הבית החדש)
2. **בדיקת הניהול:** לעבור ללשונית "ניהול ובקרה" למעלה, ולהתחבר עם חשבון
   Google שלך — **החשבון הראשון שמתחבר הופך אוטומטית למנהל/ת ראשי/ת**
   (אין צורך להגדיר את זה מראש)
3. **בדיקת הטאבלט (מהמחשב/טלפון שלך, כבדיקה בלבד):** בלשונית "ניהול ובקרה"
   → "ניהול מקוואות" → להעתיק את קישור התקנת הטאבלט → לפתוח אותו בטאב חדש
   → לאשר → זה "יקבע" את הדפדפן הנוכחי כטאבלט קבוע. להיכנס כבלנית (PIN
   לדוגמה: `1234`), לרשום טובלה או שתיים
4. לרענן את הדף — אם הנתונים נשארים, זה סימן שהחיבור ל-Firestore תקין
5. לפתוח את הכתובת במכשיר נוסף (או בדפדפן אחר/גלישה בסתר) ולוודא שאותם
   נתונים מופיעים אצל המנהל/ת — זה מוכיח שהנתונים באמת משותפים

⚠️ **טיפ לבדיקה:** אחרי שקבעת מכשיר כטאבלט קבוע (שלב 3), הדפדפן הזה "ננעל"
למצב טאבלט בכל כניסה לאתר. כדי לבטל את זה בזמן בדיקות, להיכנס למסך כניסת
הבלנית וללחוץ "ניתוק המכשיר ממקווה זה" למטה.

## איך עובדות ההרשאות עכשיו

הגרסה הזו מוסיפה שלושה מעגלי הרשאה נפרדים:

**מנהלים** (לשונית "ניהול ובקרה") — כניסה עם Google בלבד, מול רשימת
כתובות מאושרות שמנוהלת בלשונית "הרשאות". המנהל/ת הראשון/ה שמתחבר/ת
מתווסף/ת אוטומטית (bootstrap) כדי שהמערכת לא תישאר נעולה; מנהלים נוספים
מתווספים ידנית משם.

**בלנית על טאבלט מותקן** — בלי חשבון Google בכלל. המנהל/ת מפיק/ה קישור
ייעודי למקווה מסוים (לשונית "ניהול מקוואות" → "קישור להתקנת טאבלט קבוע"),
פותחים אותו **פעם אחת** בדפדפן הפיזי של הטאבלט, ומשם והלאה המכשיר נכנס
ישירות למסך שם+קוד אישי (בדיוק כמו בדוגמה המקורית).

**בלנית מהטלפון האישי** — דורשת התחברות Google, מול רשימה נפרדת בלשונית
"הרשאות" שממפה כל כתובת אימייל לשם בלנית ולמקווה ספציפי. רק כתובות
שברשימה יוכלו להיכנס; אחרות יראו הודעה שהחשבון לא מאושר.

**תושבות (ממשק ציבורי)** — בלי חשבון בכלל, כמו קודם.

## תמיכה בכמה מקוואות

יש עכשיו לשונית "ניהול מקוואות" שמאפשרת להוסיף/למחוק מקוואות. כל מקווה
מנהל צ'ק-ליסט, יומן טובלות, מלאי, פתקים, תקלות ויומן שינויים משלו לגמרי
בנפרד. בלשונית "סקירת מקוואות" (הטאב הראשון בניהול) רואים את כל המקוואות
זה לצד זה במבט אחד — סטטוס פתוח/סגור, טובלות היום, קריאות פתוחות ומלאי
נמוך — ולחיצה על מקווה עוברת לניהול המפורט שלו. בממשק הציבורי, אם יש יותר
ממקווה אחד, מוצג בורר קטן למעלה.

⚠️ **הערה על נתונים קיימים:** מכיוון שכל הנתונים עכשיו משויכים למקווה
ספציפי, נתוני בדיקה שנרשמו בגרסה הקודמת (לפני התמיכה בכמה מקוואות) לא
יופיעו יותר — הם נשארים ב-Firestore תחת שמות מפתח ישנים, אבל האתר קורא
עכשיו ממפתחות חדשים (עם מזהה מקווה בסוף). אפשר להתעלם מהם או למחוק אותם
ידנית ב-Firebase Console (Firestore → Data → אוסף `app_data`).

## מה עוד יש בפרויקט

- `src/App.jsx` — כל לוגיקת האפליקציה, כולל הניתוב, ריבוי המקוואות וההרשאות
- `src/storage.js` — "מתאם" שמדבר עם Firestore בממשק get/set/delete/list
- `src/auth.js` — התחברות Google + אנונימי (Firebase Authentication)
- `src/firebaseConfig.js` — פרטי החיבור לפרויקט Firebase שלך (כבר מוטמעים)
- `.github/workflows/deploy.yml` — הקובץ שגורם ל-GitHub לבנות ולפרוס אוטומטית

## הערות

- הנתונים ההתחלתיים לדוגמה (בלניות, מלאי) מוגדרים כברירת מחדל בקוד לכל
  מקווה חדש — הם נשמרים ל-Firestore בפעם הראשונה שמשהו נכתב, ומשם ואילך
  הנתונים האמיתיים גוברים.
- כפתור החירום וההתראות עדיין מדומים בתוך האפליקציה — SMS/Push אמיתיים
  דורשים חיבור לשירות כמו Twilio או Firebase Cloud Messaging בהמשך הדרך.
- כללי ה-Firestore (`firestore.rules`) דורשים כרגע רק "מישהו מחובר" (כולל
  אנונימית) — הם לא אוכפים בצד השרת מי מנהל ומי בלנית; זה נאכף כרגע רק
  בתוך האפליקציה עצמה (מסך "הרשאות"). לאבטחה חזקה יותר בהמשך אפשר להשתמש
  ב-Firebase custom claims כדי לאכוף את זה גם ברמת כללי ה-Firestore.
- אם בהמשך תרצי לוותר על GitHub Pages ולעבור ל-Firebase Hosting (מאפשר
  דומיין מותאם אישית בקלות רבה יותר), זה אפשרי גם מהטרמינל בעזרת הפקודות
  `firebase login` → `firebase use --add` → `npm run deploy` — אך זה כבר
  דורש שימוש בטרמינל.
