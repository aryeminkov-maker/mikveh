# רשת המקוואות — מערכת ניהול (גרסה עצמאית)

פרויקט React מלא שממיר את הדוגמה מהצ'אט לאתר אמיתי, עם בסיס נתונים אמיתי
ב-Firebase (Firestore). המדריך הזה מסביר איך לפרוס את זה **בלי טרמינל בכלל** —
הכל דרך הדפדפן, באמצעות GitHub.

---

## המסלול: GitHub בלבד (בלי טרמינל)

### שלב 1 — יצירת Repository ב-GitHub

1. כניסה ל-**github.com**, התחברות (או יצירת חשבון חינמי)
2. **"New repository"** (כפתור ירוק) → שם, למשל `mikveh-management` →
   לוודא שהוא **Public** או **Private** לפי מה שנוח לך → **Create repository**
3. חשוב: ה-branch הראשי חייב להיקרא **`main`** (זו ברירת המחדל היום ב-GitHub,
   כך שבדרך כלל אין צורך לשנות כלום)

### שלב 2 — העלאת כל קבצי הפרויקט

1. בעמוד ה-repo החדש (הריק), ללחוץ על הקישור **"uploading an existing file"**
2. לחלץ את ה-zip שקיבלת ממני, ו**לגרור את כל התוכן** מתוך התיקייה (כולל
   התיקייה הנסתרת `.github`, `src`, `index.html`, `package.json` וכל השאר)
   לתוך אזור ההעלאה בדפדפן
   - ⚠️ תיקיות נסתרות (ששמן מתחיל בנקודה, כמו `.github` ו-`.gitignore`)
     לפעמים לא נגררות אוטומטית מהגרירה הראשונה של כל התיקייה — אם בסיום
     ההעלאה את לא רואה תיקיית `.github/workflows` ב-GitHub, תצטרכי לגרור
     אותה בנפרד. זו התיקייה **הכי חשובה** — בלעדיה הפריסה האוטומטית לא תפעל.
3. למטה, **"Commit changes"**

### שלב 3 — הפעלת GitHub Pages

1. בתוך ה-repo, לשונית **"Settings"** (למעלה)
2. בתפריט הצד → **"Pages"**
3. תחת **"Build and deployment" → "Source"**, לבחור **"GitHub Actions"**
   (לא "Deploy from a branch")
4. זהו — אין צורך ללחוץ שום דבר נוסף כאן

### שלב 4 — מעקב אחרי הבנייה האוטומטית

1. לשונית **"Actions"** בתוך ה-repo
2. אמור להופיע ריצה בשם "Deploy to GitHub Pages" עם עיגול צהוב מסתובב
   (כ-1-2 דקות) ואז ✅ ירוק
3. כשהיא מסתיימת בהצלחה, לחזור ל-**Settings → Pages** — תופיע שם הכתובת
   החיה של האתר (בפורמט `https://<username>.github.io/mikveh-management/`)

מעכשיו, **כל פעם שתעלי/תעדכני קובץ ב-GitHub** (שוב, בגרירה בדפדפן, בלי
טרמינל), הפריסה תרוץ מחדש אוטומטית ותעדכן את האתר החי תוך דקה-שתיים.

---

## שלב חובה נוסף (חד-פעמי): פתיחת הרשאות הכתיבה ב-Firestore

כשיצרת את מסד הנתונים ב-Firebase בחרת **Production mode** — המצב הזה חוסם
**את כל** הקריאה/כתיבה כברירת מחדל, מטעמי אבטחה. כדי שהאתר יוכל בכלל לשמור
נתונים, צריך להדביק את כללי ההרשאה **פעם אחת**, ישירות בממשק הדפדפן של
Firebase (גם זה בלי טרמינל):

1. כניסה ל-https://console.firebase.google.com → הפרויקט שלך (`mikveh-bl`)
2. **Databases & Storage → Firestore → לשונית "Rules"**
3. למחוק את מה שכתוב שם, ולהדביק את התוכן המלא של הקובץ `firestore.rules`
   שנמצא בפרויקט שהורדת ממני
4. **"Publish"**

⚠️ הכללים האלה פתוחים לגמרי לצורך בדיקות ראשוניות — יש הערה מפורטת בתוך
הקובץ עצמו על איך לנעול את זה (עם Firebase Authentication) לפני שיש
משתמשות אמיתיות ונתונים אמיתיים (מזומן, טלפונים).

---

## בדיקה שהכל עובד

1. לפתוח את הכתובת החיה מ-GitHub Pages
2. להיכנס כבלנית (PIN לדוגמה: `1234`), לרשום טובלה או שתיים
3. לרענן את הדף — אם הנתונים נשארו, זה סימן שהחיבור ל-Firestore תקין
4. לפתוח את הכתובת במכשיר נוסף (או בדפדפן אחר) ולוודא שאותם נתונים מופיעים —
   זה מוכיח שהנתונים באמת משותפים בין כל מי שנכנס לאתר

---

## מה עוד יש בפרויקט

- `src/App.jsx` — כל לוגיקת האפליקציה (זהה לדוגמה בצ'אט)
- `src/storage.js` — "מתאם" שמדבר עם Firestore בממשק get/set/delete/list
- `src/firebaseConfig.js` — פרטי החיבור לפרויקט Firebase שלך (כבר מוטמעים)
- `.github/workflows/deploy.yml` — הקובץ שגורם ל-GitHub לבנות ולפרוס אוטומטית

## הערות

- הנתונים ההתחלתיים לדוגמה (בלניות, מלאי) מוגדרים כברירת מחדל בקוד — הם
  נשמרים ל-Firestore בפעם הראשונה שמשהו נכתב, ומשם ואילך הנתונים האמיתיים גוברים.
- כפתור החירום וההתראות עדיין מדומים בתוך האפליקציה — SMS/Push אמיתיים
  דורשים חיבור לשירות כמו Twilio או Firebase Cloud Messaging בהמשך הדרך.
- אם בהמשך תרצי לוותר על GitHub Pages ולעבור ל-Firebase Hosting (מאפשר
  דומיין מותאם אישית בקלות רבה יותר), זה אפשרי גם מהטרמינל בעזרת הפקודות
  `firebase login` → `firebase use --add` → `npm run deploy` — אך זה כבר
  דורש שימוש בטרמינל.
